# Attendance

一个简约、完全离线的 Android 点名应用。使用 Kotlin、Jetpack Compose 与 Material 3 构建。

## 功能

- 创建多个班级，在设备本地保存班级、学生和历史点名记录
- 手动添加、修改学生，或从 CSV/TXT 文件批量导入姓名和学号；名单也可导出为 CSV
- 点按学生卡片即可标记“到”，也可指定迟到、请假、缺勤、不参与及原因；最近一次修改可通过 Snackbar 短时间撤销
- 点名中支持姓名/学号搜索、未处理/已处理/异常及具体异常状态筛选；可批量填充未处理学生，或选择学生统一设置状态和原因
- 每个班级可保存多组“情况”，逐个预设学生的状态与原因；开始点名后可原子化复用并只覆写相关学生
- 有标记的未完成点名会作为独立草稿出现在历史页；空草稿不保存，清空标记后自动删除，可查询、继续修改或删除，结束点名只清理当前草稿
- 主页直接选择开始点名或开始一次独立的材料登记，点击右上角头像切换班级；材料登记可自定义名称和一份或多份材料，逐人记录未登记、已完成或不合格，创建后立即进入历史并可返回编辑
- 结束点名时自动把未标记学生记为缺勤，并显示统计与明细
- “工作 / 历史 / 设置”三个标签页，可集中查看以往点名结果
- 首页右上角提供可自定义的圆形头像图标，点击进入班级切换页面
- 可自定义常用未到原因、点按默认状态，以及姓名卡片的长按和左右滑动动作
- 到场、迟到、请假、缺勤、不参与使用不同图标和颜色，并可在设置中分别更换
- 历史记录支持删除；结果可按设置的字段生成文本、复制到剪贴板或保存为 TXT
- 班级切换页面采用圆角卡片布局；轻点切换当前班级，长按可编辑或删除班级
- 设置使用纵向分组，可分别控制学号、进度、提示、状态按钮、统计卡、空分类等内容是否显示
- 每个班级可覆盖全局点名和显示设置，班级名称、学生姓名与学号均可修改
- 支持完整 JSON 数据备份与恢复；未到原因可拖动排序

## 名单格式

推荐使用 UTF-8 编码，支持逗号、制表符或分号分隔。表头可写成：

```csv
学号,姓名
20260001,张三
20260002,李四
```

也支持 `姓名,学号`、无表头的两列文件，以及每行只有姓名的纯文本名单。导入时既可选择文件，也可直接粘贴文本。

## 本地构建

需要 JDK 17 和 Android SDK 35：

```bash
./gradlew assembleDebug
```

GitHub Actions 中的 “Build unsigned APK” 可手动运行。它执行经过 R8 与资源裁剪的 `assembleRelease`，产物为未签名的 `app-release-unsigned.apk`。

材料登记保留每名学生下面多份材料的布局，每份材料支持左滑标记不合格、右滑标记已完成，并与点名复用滑动组件。点击学生头像默认确认该生未登记的材料；遇到不合格项会提示，只有明确选择覆盖才确认全部。单项修改、清除和头像批量确认都支持最近一次操作撤销。状态统一使用 Material 颜色角色。历史中点击点名记录查看结果，点击“编辑”返回点名操作页，保留当次名单并更新原记录。

主题配色位于“设置 → 外观与头像”，支持系统主题色（Android 12 起动态取色，旧系统使用默认 Material 配色）和自定义 #RRGGBB 颜色，自动适配深浅色模式并纳入备份。材料未登记采用中性描边，已完成采用实心主题色，不合格采用 Material 错误色容器。

设置交互与班级覆写：常用原因支持长按拖动，卡片实时跟随手指，相邻项让位，靠近边缘时自动滚动，松手后统一保存新顺序。班级设置复用全局设置页面，支持按项覆写操作、原因列表与顺序、状态图标与颜色、显示、结果、历史和导出设置；每项可单独恢复跟随全局，也可全部恢复。未覆写项继续响应全局设置变化。主题、头像和整机备份统一由全局管理。旧版班级点名设置可兼容读取。材料登记新增头像批量确认、统计、提示、紧凑布局和状态按钮开关，均支持班级覆写。

## 产品核查与分阶段路线

本轮基于 `master` 的 `28ae92b`。继续维持完全离线、单机、本地数据由用户掌控的定位。以下“基线”指本轮改进前的代码，不把已有能力算作新功能。

### 已有能力与可复用结构

| 能力 | master 基线核查 | 实施判断 |
| --- | --- | --- |
| 班级、学生、CSV/TXT 名单 | 已有增删改、文件/粘贴导入和 CSV 名单导出 | 直接复用 `Student` 和 `ClassGroup` |
| 点名状态与原因 | 已有到场、迟到、请假、缺勤、不参与和自定义原因 | 不新增点名状态 |
| 多个独立草稿 | 已有 `RollCallDraft`；非空自动保存，空草稿删除，结束只删除当前草稿 | 撤销清空时按原 ID、创建时间重建当前草稿 |
| 点名历史与编辑 | 已有查看、删除、结果单项编辑、整次返回点名页编辑 | 延用当次姓名/学号快照，不从当前名单重建历史 |
| 情况与学生预设 | 已有多组 `ClassSituation`，一次应用整组，可先后应用多组，只修改所定义学生 | 已经具备模板核心能力；本轮明确“后应用覆盖前一个”、只影响本次，并提供整组撤销 |
| 材料任务和多份材料 | 已有名称、多份材料、学生名单快照、每个学生×材料独立登记 | 可利用现有记录做批量操作及导出 |
| 材料状态和历史 | 已有未登记、已完成、不合格，任务创建即保存，历史区分进行中/已完成 | “缺交”需要增加枚举及兼容校验，后续单独实施 |
| 材料任务重新编辑 | 已有 `completedAt`、`updatedAt`，“继续编辑”可恢复进行中；已完成任务也可修改单项 | 不重复实现重新打开；后续明确查看与编辑模式 |
| 设置、备份与离线存储 | 全局及班级逐项覆写、JSON 备份恢复、本地 SharedPreferences JSON、串行写入及确认/回滚快照 | 首轮不增加持久化字段，不新增设置或基础设施 |
| 历史搜索/筛选 | 尚无；点名、材料混合展示，分草稿和已完成 | 直接内存过滤现有列表 |
| 跨历史统计、学生详情 | 尚无；已有统计仅针对单次点名/任务 | 从历史快照按 classId/studentId 推导，不保存统计副本 |
| 班级归档、复制 | 尚无；目前删除班级会级联删除其点名历史、草稿及内嵌材料任务 | 归档需要一个兼容默认值的字段；复制需要一次性重建 ID 映射 |
| 汇总和材料结果导出 | 尚无；已有单次点名 TXT/复制文本、名单 CSV | 复用文件选择器及 `safeCsvCell` 公式注入防护 |
| 首页继续最近工作 | 尚无；目前首页开始新工作，历史页继续草稿 | 可按所选班级读取最近草稿/材料任务，不保存额外“最近”状态 |

主要代码位置：`data/Models.kt` 定义业务模型，`data/AttendanceRepository.kt` 负责读写、快照和备份，`AttendanceApp.kt` 包含点名、结果和历史页，`MaterialScreens.kt`、`SituationScreen.kt`、`ClassActionScreen.kt` 对应材料、情况和工作入口。

### 第一阶段：高频操作效率（本轮已实现）

- 最近一次操作撤销：点按、左右滑动、长按动作/状态选择、清除单人、清空整次、情况应用、点名批量、结果单项编辑、材料单项和头像批量操作。恢复整个操作之前的状态与原因，继续走原保存路径。
- 提示采用 Material Snackbar 的短时长（支持系统无障碍时长调整）。单人提示压缩为“张三 → 到场 / 清除”，仅保留撤销动作，省去关闭图标；批量提示保留人数和范围。连续修改替换上一条提示，不排队，不提供 redo；离开页面、结束点名或切换材料任务完成状态后失效，不写入备份。无实际变化的操作不替换上一次有效撤销。
- 点名“批量”：全班未处理→到场/缺勤，不受当前筛选影响，菜单明确说明范围；选择学生可设置状态和原因。默认跳过已有结果，只有勾选“覆盖已有状态和原因”并确认才覆盖。
- “仅修改原因”保留原状态，只作用于已选的异常学生；到场及未处理学生跳过，留空表示清除原因。
- 搜索姓名/学号；筛选栏展示全部、未处理、异常、已处理，四种具体异常收进右侧固定的“状态”菜单，选中后显示具体状态。筛选仅改变显示，进度和结束保存始终针对全班。切换搜索/筛选回到列表开头。
- 多选时顶栏切换为选择模式，显示选中人数、当前未显示人数、处理和退出；“选择当前结果 / 清除选择”收进更多菜单，不再增加名单上方的常驻按钮行。切换筛选保留已选学生，批量确认再次明确当前未显示人数；选择卡片不触发点名手势。
- 底部仅保留结束按钮；有异常时，进度区显示可点击的“异常 N”，清除搜索并展示全部异常，零异常时不显示。已有未点完确认框也提供“先复核异常”次级动作；结果页“仅查看异常”复核迟到、请假、缺勤、不参与。全班未处理仍沿用基线规则：结束时记为缺勤，按原设置决定是否提示。
- 材料头像默认保护不合格项；确认框以“只确认 N 份未登记”为主操作，覆盖动作独立用警示色标明不合格数量，并可取消；头像无障碍描述与默认行为一致。整次确认可一次撤销，并且不会改动任务创建时间、完成状态或其他学生记录。

下一小步可增加首页“继续最近点名/材料登记”：每种最多一个入口，优先于“开始”，仅对应当前班级；所有独立草稿仍在历史页，不自动合并。先观察手机上的搜索区占屏、误触恢复和筛选操作，再进入第二阶段。

### 第二阶段：历史真正可用

1. 历史顶部只放搜索和筛选入口。搜索匹配历史学生快照姓名/学号、材料任务名称；折叠筛选面板提供班级、点名/材料、日期范围、草稿/已完成，一键重置并显示结果数。各条件取交集，空结果仍保留筛选入口。
2. 日期范围按记录创建日期、设备本地日界线包含首尾两天；保留现有更新时间/完成时间排序。避免把“编辑过的旧记录”误认为新的一次点名。
3. 班级统计放在班级上下文中，提供点名次数、平均出勤率、四种异常人次、最近 5 次；学生统计提供各状态次数、出勤率、最近一次异常和最近 5 次。只统计已保存点名历史，草稿不计入。
4. 出勤率统一为 `(到场 + 迟到) / (到场 + 迟到 + 请假 + 缺勤)`，不参与及编辑中未处理不计入分母；显示有效样本数，分母为零显示“暂无”。班级“平均”按各次有效出勤率取算术平均，学生按有效次数计算，异常数标为“人次”，不混用人数。日期范围同时作用于统计和导出。
5. 学生身份以班级 ID + 学生 ID 关联，不按姓名关联。改名/移除后记录仍使用当次快照；历史中同一 ID 不断开，新建同名学生不合并。需要显示已移除学生的统计入口。
6. 单次点名补 CSV；日期范围汇总、班级/学生统计导出 TXT/CSV。采用临时字段选项，不扩大全局设置；CSV 所有文本单元格复用公式注入防护，长文本字段应扩展安全导出函数的长度参数并加测试，不绕过校验。导出必须包含统计范围和口径。

不增加缓存统计表、数据库、BI 或复杂图表；先实现列表和计数。

### 第三阶段：长期使用体验

1. 班级归档：给 `ClassGroup` 增加 `archivedAt: Long?`，旧数据默认 null；同步更新 JSON 写入、读取、校验和备份测试。正常切换/首页只显示未归档班级；全部归档时提示创建或恢复。已归档班级保留历史与草稿，可查看/导出、恢复后继续工作，仍完整备份。
2. 永久删除保持独立操作，确认中明确将删除名单、点名历史、草稿、情况和材料任务，并建议先备份。归档不调用现有 `deleteClass`。
3. 班级复制对话框提供名称、名单、情况、班级专属设置。只复制现有常用配置，不凭空引入材料模板。新班级、学生和情况一律生成新 ID，情况引用按学生 ID 映射；未复制名单时情况选项禁用。历史/材料任务/草稿始终不复制，新班级默认为未归档。
4. 轻量学生 Bottom Sheet 从名单、点名及统计打开，显示姓名、学号、班级、各情况赋值及第二阶段统计/最近记录；被移除学生由历史快照打开，不建立学生档案模型。
5. 情况仅增补多组选取和冲突提示：用户选择的应用顺序决定覆盖顺序，一次应用和一次撤销。保留原组名与学生赋值，不修改源情况，不建立优先级模型。

班级复制与详情可复用结构；只有归档增加一个持久化字段。学期概念先通过归档、复制和日期范围解决，不引入 Semester。

### 第四阶段：材料登记语义完善

1. 增加 `MISSING`（缺交），`PENDING` 保持“未登记”；旧数据不推断、不自动转换。更新所有 UI 分支、JSON/备份校验及兼容测试；含新状态的备份需提示旧版本可能无法恢复。
2. 结束时按学生×材料计算剩余未登记项，提示“保持未登记并完成 / 标为缺交并完成 / 返回继续”。转换和完成状态一次保存，不静默批量改值；允许整次撤销恢复原登记及进行中状态。
3. 利用已有 `completedAt`：已完成打开先查看，明确“重新编辑”后转为进行中，保留 createdAt、更新 updatedAt；改完再次完成。整理现有交互，不新增一套任务生命周期。
4. 批量确认覆盖全任务未登记、选中学生、某一种材料；默认保护不合格和缺交。若要覆盖，应明确范围、数量并另行确认；统一使用本轮一次操作撤销。
5. 材料统计与 TXT/CSV 导出区分已完成、不合格、缺交、未登记。提供每种材料明细及学生清单，不把未登记视作缺交。

新增材料状态比搜索或统计更具兼容成本，需单独完成迁移、结束/恢复操作、备份往返及四状态统计的验证后再上线。

### 验收方式

自动验证：`./gradlew lintDebug testDebugUnitTest assembleDebug assembleRelease`，重点覆盖最近提示替换与失效、安全批量、只改原因、筛选不改数据、材料整次撤销与过期保护、草稿清空恢复、历史快照及备份往返。

基线测试核查：未修改的 `28ae92b` 有两条旧断言与代码语义不一致。本轮校正为历史允许清除后的 UNMARKED，但草稿/默认状态仍拒绝 UNMARKED；重复原因备份仍严格拒绝，并验证拒绝后原数据不变。未放宽备份校验。

手机人工验收（发布前）：

- 60 人班级先标记 5 人异常，再将未处理批量到场；5 人状态/原因不变，撤销后恢复整批未处理。
- 搜索学号、通过“状态”菜单只看缺勤、多选跨筛选学生；顶栏和批量确认显示准确的未显示人数，操作范围和人数准确，筛选结束不丢数据，无结果时可恢复全部。
- 连续误滑两名学生，仅最后一次可撤销；清空草稿后立即撤销，另一个独立草稿不变；离开后提示失效。
- 在结果页及历史编辑页修改改名/已移除学生，撤销后原快照仍正确。
- 一名学生有已完成、不合格、未登记各一份；头像默认仅填未登记，明确覆盖后能一次恢复三份原状态。
- 500 人名单及较大字体、窄屏上检查搜索/多选布局、流畅滚动、Snackbar 可达性；输入法弹出时仍能退出搜索。此为验收目标，不能将编译成功当作真机交互验证。

核心观察指标是完成常见场景的点击次数、误操作恢复步骤和找到异常/历史记录的时间。首轮期望把“逐一填写剩余学生”缩短为打开批量菜单并选择操作，把误点恢复缩短为一次撤销；具体体验需以上述手机场景验证。
